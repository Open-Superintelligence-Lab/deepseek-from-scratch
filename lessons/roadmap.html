COURSE ROADMAP · THEORY FIRST

Understand the architecture, then test its design choices

Our backbone is the DeepSeek-V4.1-Flash technical report. Start with what each component does and what information it passes onward. Work through memory, attention, expert routing, and Engram with concrete examples. Then read a result from the paper and try the optional code and experiments. You can follow the theory without running a training job.

READ AND EXPLORE 1 · See the whole architectureFollow the encoder, decoder, attention, experts, and learned memory on the paper’s diagram. 2 · Distinguish weights, states, and cachesFollow one input and identify which information is learned, computed, or saved for later. 3 · Understand what caching reusesSee why old keys and values remain valid when the sequence grows. 4 · Compare three attention design choicesCompression, sharing, and sparse reading solve different parts of the cost problem. 4b · Store the main cache in FP4Try rounding and shared scales; separate the main cache from the local FP8 cache. 5 · Follow sharing and sparse selectionCalculate two reads from the same memory, then follow the indexer and hierarchical selection. 5b · Rebuild missing local cacheFollow a saved conversation through global-cache reuse and approximate local replay. 6 · Route a token through expertsSee what the router chooses, how outputs combine, and what happens when workloads are uneven. 6b · Mix residual streams in one passMove an input-mixing decision earlier and see which repeated memory read disappears. 7 · Understand Engram lookup memoryFollow n-grams, tables, collisions, and contextual gates through the existing separate clips and explanations. 7b · Draft and verify several tokensSeparate proposing tokens, checking them, and choosing how many to verify. 7c · Construct useful training tasksTry three candidate fixes against weak and stronger tests to see what a reward can miss. 8 · Read the evidence in the paperInspect a real comparison, understand what it supports, and identify what remains untested.
Optional practice: code and experiments already available
  1. Trace the NumPy attention implementation. Fixed random weights isolate the calculation.
  2. Inspect a real small training run. Code, synthetic dataset, settings, weights, loss curve, and samples are saved.
  3. Check caching correctness and measure storage. Runtime measurements are specific to this small CPU setup.
  4. Read the official packed-table code and fix an offset.
  5. Try the illustrative Engram lab. Its table examples are not trained model results.
